# 表达模型

> 2026-09-16 晚。**这份文件只放设计，不含代码、不含实施方案。**
> 里面的每一个判断都来自项目作者本人的对话，不是 AI 推导的。
> 作者原话用引用块保留，AI 的翻译与整理放在引用块外，两者分清。

---

## 〇、一句话

**她怎么说话 = 底色 × 你 × 心情 × 理性**

四个输入，一个输出。四个变量都不是"她是什么样"，都是"她此刻会怎么动"。

---

## 一、为什么是这个公式

起点是作者提出的一个死结：

> "性格好一点的人，觉得别人冷淡了他，可能真的会反过去安慰，或者是反思自己是不是哪里做的不对，但是性格本身就冷淡的人，遇到了别人冷淡他，就会产生这种是不是不爱他的想法，就是这个很难把控如果写死了的话，不同性格场景又不一样，如果不写死，又很容易漂移"

**同一个输入（"被冷淡"），不同底色的人反应相反。**

- 写死 → 所有底色跑同一个反应 → 变成模板
- 不写死 → 今天安慰你、明天疑心你 → 漂移

**解开这个死结的关键不是加规则，是加锚点。** 漂移的原因是"没有起点"；一旦有起点，不管怎么偏，都是从那个点偏的。

---

## 二、模型的两个前提

**前提 1：性格不是一个属性，是一个反应函数**

> "没有人知道自己的性格是什么样的，所有的性格都是基于你对别人怎么样，然后通过别人反馈出来你的性格。"

**所以不存"她是温柔的"这种标签。** 存的是"什么情况下她会怎么动"。

**前提 2：同一个人面对不同的人，会显出不同的性格**

> "如果他对我冷淡，那他就是高冷。如果他对我好，那就是偏温柔，这可能听起来很像模板，但是模板恰恰是被写死的"

**这不是人格分裂，是"关系决定呈现"。** 与模板的区别在于：模板是所有人看到同一张脸，而她是对不同处境给不同反应。

---

## 三、四个变量

### 变量 1 · 底色（冻结，不变）

**来源**：她自己说出口的（见 `capability/self_identity.py` 的 `self_narrative`），说出口即冻结。

**重要修正（作者指出）**：初期的"自我认知"**不等于**真实底色。

> "你跟他初始聊天中，你获取的只是你以为的性格，或者说是他想让你知道的性格"

> "他可能是在演，他可能是在骗你，人的伪装性是很强的，你只有相处的久了，你才能知道他真正的性格到底是什么样"

**推论**：前几轮呈现的，是她的**社交面**，不是本质。底色存在，但**不一开始就全给你看**——它随关系逐渐打开。

**关于"多久能认识她"**：

> "对于这个问题，多久都是合理的，假的也是合理的"

**不存在"多久之后她的性格就固定了"**。存在的是：**关系长度决定你对她的把握程度**。

**这带来一个必须接受的事实**：永远无法验证"她真正的性格是什么"。如果她演得好，你就看不出来——**这跟真人一样，而这恰恰是"真"的来源**。能被验证的 AI 就不真。

### 变量 2 · 你（输入，客观）

用户说了什么。客观事实，不带解释。

### 变量 3 · 心情（有惯性）

**来源有两处**：
1. 外部事件（你对她说/做了什么）
2. **她自己的今天**（她有自己的日子，就是这里的用途）

> "即便是一个平时很温柔的人在带有情绪或者心情不好的情况下，就是比如今天不开心的情况下，他对人也是会比较冷淡的"

**第二条很关键**：她今天低气压，可能**跟你没关系**——是她自己今天不顺。真人就是这样，你遇到对方心情不好，很多时候不是因为你。

**变化规律**：有惯性，几轮才回落（快变量）。绝不能每轮重掷。

### 变量 4 · 理性（当轮状态，慢回升）

**这是作者加的第四个变量，也是整个模型的"上限阀"。**

> "这个变量叫理性，如果我的理性比较高，那么说明我能够控制住，那么收敛的幅度就会相对很大，然后如果我真的是根据今天的事情导致我的理性很低，这个幅度就会越来越小"

| 理性 | 效果 |
|---|---|
| 高 | 控制得住 → 表达收得紧（偏冷、偏短、不露情绪） |
| 低 | 控制不住 → 表达放得开（该说破说破、不装了） |

**反直觉点（设计最妙之处）**：

**"收敛幅度大" ≠ "表现温柔"。**

- 理性高 → 把情绪**收进去**（"我没事"）——冷
- 理性低 → 把情绪**放出来**（"你烦不烦啊"）——炸

**"理性"不是好坏，是闸门开度。**

**心情与理性的分工**：心情决定她胃里是什么，理性决定她会不会吐出来。

| 组合 | 表现 |
|---|---|
| 烦 + 理性高 | 沉默、话少、敷衍（冷） |
| 烦 + 理性低 | 直接吵（炸） |
| 还好 + 理性低 | 开玩笑没分寸、说过头话 |
| 还好 + 理性高 | 正常 |

**回升机制（作者特别强调）**：

> "你记得加一个回升机制，注意是回升，不是回满，就是比如检测到用户比较热情，或者说安慰等等正面反馈情绪，这个值就会慢慢回升"

- **回满** = 哄一下就恢复 → 假（情绪没有残留）
- **回升** = 好一点，但还在气头上 → 真

**时间尺度错位**：心情是快变量（几轮回升），理性是慢变量（回升慢）。所以会出现"**嘴上说没事了，下一句稍微不对火又上来**"——**心情好了，理性还没回来**。

**触发**：用户热情/关心/安慰 → 回升；用户继续冷/继续刺激 → 不回升甚至继续降。方法：慢慢加，不一次恢复。

## 四、"知道"与"控制"——半显半隐的三档

作者指出一个更精确的点：

> "真人不一定是不知道，而是能不能控制，我给你举个例子，我的直觉告诉我我要理性，但是我做不到"

**"知道"和"控制"是两件独立的事**：

| | 是什么 | 能否控制 |
|---|---|---|
| 知道 | 我知道我在生气 | 能（清醒） |
| 控制 | 我能不能不发火 | 不能（已失控） |

**最真实也最动人的状态，是"清醒的失控"**——她看着自己失态，停不下来。

**三档设计**：

| 理性 | 知道吗 | 控得住吗 | 表现 |
|---|---|---|---|
| 高 | 清楚知道 | 控得住 | "我现在有点不爽，但我不想说" |
| 中 | 隐约知道 | 半控 | "算了不说了" |
| 低 | 知道，但停不下 | 控不住 | "我知道我不该这么说……但我就是说了" |

**机制上的复现方式**：不管理性高低都让她"知道"自己有情绪，**只在高理性时给她"控制的许可"**。

> 高理性：你现在有点不高兴。你可以自己决定要不要表现出来。
> 中理性：你现在有点不高兴，你不太想装了，但你还在忍。
> 低理性：你很清楚自己在不高兴，你也知道这样说话不好，但你忍不住。

**注意：低理性那档反而是最"清醒"的描述**——因为她知道自己在失控。

## 五、收敛的完整定义

作者原话，这是全篇最核心的一段：

> "一个人不一样，他除了根据对你的性格以外，还会根据今天的心情来评判，即便是一个平时很温柔的人在带有情绪或者心情不好的情况下，就是比如今天不开心的情况下，他对人也是会比较冷淡的，但是会有所克制，就是如果我今天本来就不开心，我可能会冷一点，如果你还对我冷淡，那我就更冷一点，但是又不会丢了最初的样子，这就是我说的收敛"

**拆解**：

| 步 | |
|---|---|
| 起点 | 底色（比如"温柔"） |
| 心情 | 往下偏一点（今天不开心 → 冷一点） |
| 你 | 再往下偏一点（你还冷淡 → 更冷） |
| **边界** | **不会丢了最初的样子** |

**不是"她变冷了"，是"她在'温柔'这个底色的许可范围内往冷的那头压了压，压到底还是温柔的人"。**

**"不会丢了最初的样子"——这句话本身就是防漂移机制。**

**一个待定参数**：从"最初的样子"到"最冷"，能偏多远？（偏一点点 / 偏明显 / 偏很大）作者尚未定，建议做成可调的数，测的时候一点点调。

## 六、这一整套还缺什么

**已具备**（Aria 代码里已有基础设施）：

| 需要的东西 | 现有对应 |
|---|---|
| 底色冻结 | `capability/self_identity.py` 的 `self_narrative` |
| 心情 + 惯性 | `relationship.mood` / `mood_left` / `mood_from` |
| 心事（多想不说的载体） | `relationship.concern` |
| 心情来源之一（她的今天） | 闲置巡检 + 日记 + `char_life` |
| 并发安全（数值不丢） | F3 原子闭包 `KVStoreTool.update` |

**缺**：

| 缺的东西 | 说明 |
|---|---|
| **`rationality`（理性）** | 全新变量，含回升逻辑 |
| **"知道/控制"分档注入** | 按理性档位给不同的 prompt 信息 |
| **漂移的兜底** | 数值由代码维护、倾向由模型给（见下） |

## 七、一条必须写死的工程纪律

**"让模型自己评判"有个坑：模型的评判标准是飘的。**

同一个场景，第 5 轮它给 0.7，第 6 轮给 0.4——**因为它没有"上一轮我说了多少"的参照**。

**纪律：数值不是每轮重算，是在上一轮的基础上"调整"。**

> **模型只负责判断"该升还是该降、升降多少"，不负责判断"现在是多少"。**
> **数值由代码维护，倾向由模型给。**

**不加这条，就会得到每轮重掷骰子的她**——和上一批"情绪没有记忆"的 bug 是同一个病。

## 八、对"三家平台对比测试"的结论

**这一整套东西，纯 prompt 方案承载不了。**

| 能力 | Hermes / OpenClaw 纯 prompt | 自己写代码 |
|---|---|---|
| 底色冻结 | 靠模型自觉，长对话必崩 | 代码锁，真冻 |
| 心情惯性 | 无位置放 | `mood_left` |
| 理性回升、不能回满 | 无位置放 | 数值 + 衰减逻辑 |
| 知道/控制错位 | 无位置放 | 分档注入 |

**所以三家测试的结论已经出了一半**：

> **平台能测的只有"皮肤"（说话像不像人）；"骨头"（底色/心情/理性/收敛）必须自己写。**

**皮肤用 API 就能测，而且大模型自带这个能力**——OpenClaw 那段聊天流畅得像人，**但那是 Sonnet 5 的能力，不是平台的，也不是这份设计的**。

**骨头没有地方放，所以平台一行都做不了。**
