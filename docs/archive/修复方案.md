### ☐ A1 · `tools/storage.py` 缩进事故 —— 日记子系统整体死亡 ⭐

**修什么**：`tools/storage.py:251-370`

**怎么修**：`_log1p_safe`（242-249 行）是模块级函数，249 行就 `return 0.0` 了。它后面那 7 个方法仍是 4 空格缩进，于是全部嵌进了 `_log1p_safe` 内部、位于 `return` 之后 —— 成了永远执行不到的死代码。

改法：把 `_log1p_safe` 整个函数**剪切到文件最末尾**，然后把 251-370 这段的缩进层级还原成 `VectorStoreTool` 的类方法（和上面的 `search_memory` 同级）。

涉及的 7 个方法：`upsert_diary`、`search_diary`、`list_diaries`、`delete_diary`、`list_diaries_enriched`、`list_memories`、`delete_memory`。

**解决什么**：

| 调用方 | 现在的行为 |
|---|---|
| `capability/diary.py:168,182,187,190` | AttributeError → 被 `diary.py:74` 的 `except Exception: return ""` 整个吞掉 → **日记永远写不成，且无任何报错**。手动路径还先白烧两次 LLM 调用再失败；巡检线程每轮重试每轮无声失败 |
| `capability/memory.py:203` | AttributeError → `:205` 吞掉 → `bundle.diaries = []` → **她永远召回不到自己的日记** |
| `interaction/api.py:848,855,865,872` | 四个 REST 端点 500 → **前端记忆/日记管理页全挂** |

`git show 6026ddc:tools/storage.py` 可证：上一提交这 7 个都是正常类方法（缩进 4、在类体内），`_log1p_safe` 根本不存在。**是本次提交的回归。**

### ☐ A2 · `orchestration/pipeline.py` 裸 `session_id` —— 工具链每轮必崩 ⭐

**修什么**：`pipeline.py:651`、`813`、`830`、`843`、`1057`，共 5 处

**解决什么**：

- `813/830/843`：`except _ReviewReject` 处理器内 NameError 逃逸（不会被同级 `except Exception:844` 接住）→ "已推过内容 + 审核不过"的整轮降级变成 error；`:813` 被 `:844` 吞掉后走 `generate()` 整段重发，**语义被偷换**。

### ☐ E4 · 正则抽取的误报

**修什么**：`capability/memory.py:470`（age）、`:468`（nickname）、`:484-488`（`_is_negated`）

**怎么修**：

1. **`age`** 正则 `我[\u4e00-\u9fa5，, ]{0,10}?(\d{1,2})岁` 会把 **"我奶奶今年80岁" 收成用户年龄 80**。收紧主语，排除"我 + 亲属称谓"。

3. **`_is_negated`** 只看匹配起点前 2 字，而所有 pattern 都以"我+动词"锚定 —— **注释举的"我不叫X / 我不住在Y"根本不可能匹配到那个位置**，这个守卫近乎死代码。改成在匹配 span **内部**也查否定词。

**验证**：单测三个反例句子（"我奶奶今年80岁"、"我叫了个车"、"我不叫小明"），断言抽不出错误事实。

你现在 `.env` 里配了 token 所以没激活 —— 但 **`.env.example:70` 正在引导用户（也就是未来的你）进入这个模式**："本机/内网自用可留空"。

### ☐ F7 · 传输架构（这是取舍，不是 bug，你自己定）

双端口 HTTP 8000 + HTTPS 8443 是为 Via WebView 的麦克风怪癖打的补丁，代价是**明文面 + 两份 lifespan**（见 I10）。

**不建议做**：速率限制、RBAC、CSRF token、上传内容扫描 —— 对这个威胁模型全是过度工程。

## 不要做的事（这份清单和上面一样重要）

### 1. 不要加更多提示词

prompt 已经 **~25 段 / 3.0-3.5k 汉字 / 3-5k tokens 每轮**（还没算 12 轮上下文 + 摘要）。规则在两个主人手里已经在打架（见 H7）。

要做的是**相反方向**：把不变核压到 **≤200 tokens**（名字 + 3 个她自己认下的特质 + 2 个口癖），永远放最前、永不改动；把 mood/calm/concern/stage/时间等易变项**明确标注为"此刻的、会过去的"**，移出核心块。

## 附录 4：一个更简的架构（长期方向）

> 这不是"重写"，是收敛。做完批次 A-K 之后再考虑，或者边做边靠拢。

现在表达层有**七套机制各自往同一个 prompt 里塞话**，外加四张飞轮表、两处身份描述、三条写回路径。它们**互相不可观测**，这正是 12 轮测试"分不清能跑还是没跑"的原因。

### 收敛后的形态

1. **一个每轮算一次的 `ExpressionState{mood, energy, quirk|None, must_split}`**，序列化成 ≤3 行提示词。mood 决定 energy（terse/normal/verbose），负面抬高 snark、压低 pride+clingy。**让 mood 成为行为分布的偏置，而不是装饰。**

2. **常规轮不调感知 LLM** —— 意图/情绪走已有的词表（`perception.py:18-32`），只在长消息、情绪词命中或词表歧义时才升级到 LLM。

3. **一次"记忆整理"post-reply 调用**，一个 JSON 同时产出：identity 候选 + hard_facts + portrait + concern 更新 + mood 对账。替掉现在的 3-4 次调用（身份抽取、画像刷新、仲裁、narrative）。

4. **从话语反标定状态**（C6）取代"把状态注入然后祈祷"。**这是"像人"性价比最高的一刀**，因为它保证数字与说出口的话永不打架。

5. **身份按预算披露**（G1-G4）、fill-only 冻结、允许一次改口入账（G5）。

6. **记忆层保留** `apply_fact` + 向量库 + 闸门，但把 `prune_candidates` 接上（E1）、列表字段入闸（E3）、加 `pending_writes` 补偿队列（J2）。

7. **system prompt 收敛到 ≤1k tokens 的不变核 + 一个显式标注为临时的状态块。**

8. **写回只有一条路径**（J11），**兜底话只有一张表**（H4），**身份描述只有一个来源**（H5）。

### 净效果

| | 现在 | 收敛后 |
|---|---|---|
| LLM 调用/轮 | 2.4（稳态）~ 7（最坏） | **~1.2** |
| 污染门 | 3 扇敞开 | 关闭 |
| 状态与话语 | 可以打架 | 构造上不可能打架 |
| 可观测性 | 七套机制互不可见 | 一个对象，可断言 |
| prompt | ~25 段 / 3-5k tokens | ≤1k 不变核 + 临时状态块 |

### 关于"像人靠架构不靠提示词"

`ARCHITECTURE.md` 第一节这句判断是对的，而且**兑现的那一半是真材实料**：

| 架构真正拿住的 | 证据 |
|---|---|
| 心情惯性 | `mood_left` 逐轮倒数，12 轮记录里"别扭"撑了 3 轮 |
| 关系数值对输入敏感 | turn 6 被骂 → intimacy 6→5（**12 轮里唯一一次下降，且是对的**） |
| 心事强度衰减 | `memory.py:768` ×0.9，安抚轮减半 |
| 身份冻结原子性 | `self` 在 `_KV_UPDATE_TABLES` 白名单内，SQLite 锁内 fill-only |
| 并发不丢更新 | 8 线程 ×25 次真并发测试通过 |
| 间隔感知 | turn 9（时间拨回两天）她开口"这才闲下来啊，这两天是不是都在连轴转" |
| 会记错 | turn 10 她承认"具体哪天有点记不清了"，但记得"你怀疑我是不是AI"和"面试搞砸" |

**没兑现的那一半：状态对表达没有任何约束力。**

所以准确的分工应该是：**架构负责状态的持久化与一致性（这部分你做成了），提示词负责措辞（这部分模型自己就能做），而"状态 → 表达"这条边目前两边都没管。** C6 就是补这条边。

用你自己的话说：骨头长对了，但**骨头和皮肤之间没有肌腱**。
