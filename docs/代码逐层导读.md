## 入口层

### `main.py`（157 行）

| 行 | 东西 | 为什么这么写 |
|---|---|---|
| 27 | `_LOOPBACK_HOSTS` | 只听 127.0.0.1/localhost/::1 时不需要口令。这条判断决定了后面要不要自动生成 token |
| 30-55 | `create_app()` | 建应用对象 + 挂 lifespan。**重点是"包一层"而不是覆盖**（L38）：gradio 挂在 `/ui` 时会把自己的 lifespan 塞进 `app.router.lifespan_context`，直接赋值会把 gradio 的 startup 事件丢掉，`/ui` 直接废 |
| 41-52 | `lifespan` | startup 调 `bootstrap()` + 起闲置巡检线程；shutdown 在 `finally` 里 `watcher.stop()`。装配和服务起在这一步，import 本模块零副作用 |
| 59 | `app = create_app()` | 模块级建好，`uvicorn main:app` 才能用。代价：那种方式没有证书也没有 8443 |
| 66-82 | `_upsert_env_token` | 只替换 `ACCESS_TOKEN=` 那一行，其余（真 API key 都在同文件）原样保留。逐字不动是安全的底线 |
| 85-123 | `_ensure_access_token` | 对外监听又没配口令时**自动生成**随机 token 写进 .env，而不是拒绝启动。注释给了理由：前端已经内置"401 → 弹框 → 存 localStorage → 刷新"的完整链路，自动生成后体验是通的；拒绝启动会让人以为程序坏了。注意 L114-117：写完还得 `get_settings.cache_clear()`，否则 lru_cache 里的旧实例仍读到空口令，等于没设防 |
| 126-152 | `run()` | 口令兜底 → `ensure_cert()` → 有证书就开 8443 守护线程 + 主线程跑 8000，否则只有 8000。**双端口只能这么实现**：应用对象管不了第二个端口，所以 `uvicorn main:app` 天生出不了 8443 |

### `run_local.py`（10 行）

只剩一句 `from main import run`。留它是为了兼容旧的启动习惯，行为与 `python main.py` 完全一致——以前两个入口会分叉（一个有证书一个没有），C 批统一了。

### `bootstrap.py`（93 行）——组合根

全项目唯一允许"跨层向上 import"的地方。装配职责本来就要知道所有层的存在，把它关进一个文件，其他地方就全是干净的向下依赖。

顺序是依赖顺序，每步独立 try：

| 行 | 服务 | 备注 |
|---|---|---|
| 25 | `logger` | — |
| 34 | `kv_store` | 和 vector_store **各走各的 try**（注释在 L31-32）：以前共用同一个 try，vector_store 初始化失败就把 kv_store 一起带走，等于全部持久化失效 |
| 40-50 | `vector_store` + `ensure_ready()` | 构造函数只建 client/embedder，**删库重建的重活挪到 `ensure_ready()` 由组合根显式调一次**。否则任何人 new 一下都可能悄悄触发重建 |
| 52 | `tool_registry` / `tool_executor` | — |
| 62-70 | `diary_writer` + 注入工具 | 真身在 capability 层，这里把 `run_as_tool` 注册成 `diary_write` 的 handler。延迟 import 避开循环依赖，依赖方向仍是 capability → tools |
| 73 | `llm` | — |
| 81 / 88 | `asr` / `tts` | 没配 key 也算成功注册，用到再报错 |

## `interaction/`

### `api.py`（956 行）——最大的外围文件

**路由分工**

| 行 | 接口 | 备注 |
|---|---|---|
| 232 | `POST /api/chat/send` | 非流式。走 `handle()` + `renderer.render`（render 里有秒级同步网络调用，L249 扔线程池，别堵事件循环） |
| 252-259 | `_wants_voice` 兜底 | 用户点名要语音但 AI 这轮没标 `<voice>` → 把简短正文补合成一条 |
| 268 | `POST /api/chat/stream` | SSE。`astream(synthesize_voice=True, want_voice=_wants_voice(text))` |
| 308-311 | 断连检测 | `await request.is_disconnected()` → `TURN_REGISTRY.cancel(session_id, turn_id)`，别让后端继续烧 token |
| 318 | 响应头 | `Cache-Control: no-cache` + `X-Accel-Buffering: no`。后者只对 nginx 有效，**经 cpolar 会不会被缓冲没测过** |
| 322 | `POST /api/chat/cancel` | 前端打断时打这个 |
| 333 | `GET /api/chat/history` | 拉历史时统一剥 `<voice>` 标签（L357-360），展示用干净正文，语音内容另存 `voice_text` |
| 365 | `POST /api/chat/voice-replay` | 同一段话只合成一次，`get_cached_voice` 命中就直接返回 |
| 390 | `POST /api/chat/upload` | 白名单不含 `.svg`（L401-402，SVG 能内嵌 `<script>`，存成静态文件后被同源执行会读走 localStorage 里的口令）；分块读边写边累加（L416-425），超限立刻删半成品——先读进内存再判断会 OOM |
| 439 | `WS /api/voice/stream` | 三条语音路由共用这一个端点 |

**语音 WS 的几个细节**（L439-620）：
- 攒 buffer，收到空帧（客户端发文本）表示说完；控制帧 `{"voice": "音色名"}` 单独解析（L144 `_parse_voice_control`）。
- buffer 上限 10MB（L23，≈16kHz mono 5 分钟）：客户端一直发二进制帧却从不发 END 会无界增长到 OOM，到上限清空并提醒用户（L596-601）。
- 每条链路的处理都包了 `asyncio.to_thread`（L501、L544、L561）：ASR+LLM+TTS 是几十秒的同步网络调用，不扔线程池整个事件循环会一起卡死。
- 失败时 `manager.report_failure(session_id)`（L575），连续 2 次自动降回 cascade。
- `finally`（L608-620）里两个 close 各自独立包 try：`realtime_client.close()` 抛异常绝不能让后面的连接簿清理被跳过，否则 `ConnectionKeeper` 残留死会话。

**安全两个件**
- `_TokenGuard` L809，中间件不是依赖。免鉴权路径只有 `/static/`、`/ca.crt`、`/manifest.json`、`/sw.js` 和根路径 `/`（L824）——根路径必须放行，PWA 壳 HTML 要先加载出来 JS 才能弹口令框。`/uploads/` **不在**免鉴权里，只能靠查参 `?token=`。
- 比较用 `hmac.compare_digest`（L856），两边先 encode。别用 `==`，会泄露长度/前缀。
- `_NosniffStaticFiles` L870：覆盖 `file_response` 给每个静态响应补 `X-Content-Type-Options: nosniff`。StaticFiles 不方便按目录统一加头，这是最小改法。

**其他两个辅助函数**（这两个是 interaction 层少见的"懂内容"的地方，读的时候别跳过）：
- `_build_realtime_instructions` L26：拼 realtime 开场白，= 人设 + 语音通话规矩（L53-63，含"情绪不能写进转写文字"）+ 关于用户的记忆 + 最近 6 轮。每次建连接注入一份。
- `_realtime_writeback` L101：实时专线每轮落账，和 pipeline 的 `_writeback` 保持规矩一致（短期记忆、chat_log、蒸馏、亲密度），所以打字聊天和语音电话共用同一份上下文。

### `gateway.py`（165 行）

收发与渲染，不理解内容。

- `extract_voice` L64：拆 `<voice>`，返回 `(voice_text, clean_text)`。用的是 `re.search` 取**首个**匹配（`_VOICE_RE` L23，`re.S` 跨行），所以模型吐了两个标签也只用第一个；找不到标签时顺手把可能残缺的标签文本清掉（L74），防止 `</voice` 露在对话里。
- 语音缓存 key 是 `文本 + 音色 + 模型` 的 md5（L36-44）。只按文本算的话，换了音色还会命中旧音频，用户会觉得"换了设置没生效"。
- `MessageReceiver.receive_voice` L93：识别失败就抛，让上层降级，不返回假成功。
- `OutputRenderer.render` L110：合成失败只留纯文字（L130-132）；`output_mode=="image"` 但文件不在就降级成纯文字（L133-138），免得前端拿个空路径干瞪眼。

### `voice.py`（39 行）

`VoiceStreamIO` L6，把 WebSocket 包成音频流通道。`read_chunk` L20：收到文本帧返回空字节，上层当控制信号；`last_text` 存着最近一条文本帧的内容，控制指令从这里取。就这点职责。

### `ui.py`（78 行）

Gradio 兜底页。`build_gradio_app` L25，自己的 `DialoguePipeline()`（L27，与 api 里那个是不同实例，但共用模块级的 `KEEPER`，所以上下文是通的）。每个新页面发一个独立会话号（L53-61），多窗口不串。

| 行 | 方法 | 干什么 |
|---|---|---|

**`DialoguePipeline`**

- `handle()` L399：消费者。**每个 token 都是同样的数据流**，为了减少主观舛误，它把 `<voice>` 重新包回去（L442-445）让下游 renderer 照旧干活。要注意 L435（`error` 事件 → llm 兜底话）和 L437-439（取消 → 空 FinalReply）。
- `astream()` L454：唯一实现。步骤表见全景文档第 3 节。三个 except 分支（L546/549/552）全部收敛成事件，`finally` 登出（L555）。
- `_astream_chat` L558：真正的流式。**这里最容易看漏的一处**是 L566-570 的注释——不能用 `streamer.emitted_content` 当审计判据，因为"装配器产出过片段"和"真的推给用户了"是两回事，首句被拦时会误判成"已推过"从而直接降级。所以单独维护了 `pushed` L570。
  - L583-600：收尾时的 `held` 裁决。只有 `_is_onechar_reply` 命中才重写；"好的。" 这种正常短句直接放行。
  - L611-626：统一裁决——`pushed` 就降级，没推且 `attempt < 2` 就重写（两种重写共用同一个 attempt 计数和上限），否则降级。
  - L627-645：异常。推过内容就按现有内容收尾；一个 token 都没推就退回 `generate()` 整段重发（含人设覆盖）。**注意这里区分了 `_RefuseTurn` 要往上抛而不在这儿兜底**（L608-610）。
- `_astream_tool` L656：工具链。注释（L657-659）明说不做审核重写。
- `_emit_frag` L676：片段转事件的唯一出口。句子和 `<voice>` 内容都在这里过 `SafetyReviewer`（L689 / L701），**先审、后合成**，审不过抛 `_ReviewReject`。
- `_check_cancel` L720：静态统一的检查点，被四处调用。
- `_safety_precheck` L727 / `_perceive` L733 / `_compose` L751 / `_toolcall` L771 / `_respond` L800 / `_writeback` L813：节点实现。
  - `_perceive` L733 并行：意图/情绪（一次 LLM）与记忆召回（两次向量检索）互不依赖，扔两线程池并行，总耗时取较慢者。

## 几个跨层的实现约定（改动前先读）

1. **layer 依赖只能向下**，唯一例外是 `bootstrap.py`。
2. **数据结构定死在 `shared/types.py`**，字段名就是契约。
3. **慢同步调用必须 `asyncio.to_thread`**：renderer.render、renderer.render_voice、TTS/ASR、每次 SQLite/向量读写在 WS 路径上也包了。语音通话期间堵住事件循环会让所有连接一起僵死。
4. **出错路径上的人设读取必须能失败**：`_persona_fallback`、`FallbackController.fallback_reply`、`InfoGapCoordinator.ask` 三处都是 try/pass 之后落回内置默认。
5. **577 行那样的注释不要删**：`toolcall.py:206-224` 和 `pipeline.py:23-27` 记录的是取舍，删了就等于把设计意图连同代码一起丢掉。
